## LLM 훈련하기 ##

### 1.1 언어모델은 무엇을 학습하는가 ? ###

언어모델이 배우는 것은 단 하나, **"앞 내용이 주어졌을 때 다음 토큰이 무엇일지"** 다.

```
입력:  "파드는 쿠버네티스에서 생성하고 관리할 수 있는 배포 가능한 가장 작은"
정답:  " 컴퓨"   ← 모델이 이 토큰에 높은 확률을 주도록 가중치를 조정
```

학습 loss 는 정답 토큰에 준 확률의 음의 로그(negative log-likelihood)다.

```
loss = −log P(정답 토큰 | 앞 문맥)
  정답에 확률 0.9 를 줬다면   loss = 0.105
  정답에 확률 0.1 을 줬다면   loss = 2.303
```

수조 개 토큰으로 이걸 반복하면 모델은 문법, 상식, 사실 관계를 **다음 토큰을 잘 맞히기 위한 수단으로** 익힌다.
"쿠버네티스에서 가장 작은 배포 단위는" 다음에 "파드"를 맞히려면 그 사실을 알아야 하기 때문이다.

> **핵심:** 지식 주입이란 결국 **해당 도메인 문서에서 다음 토큰을 잘 맞히게 만드는 것** 이다.

### 1.2 다섯 가지 방법 비교 ###

| | 사전학습 | **계속 사전학습 (CPT)** | 지시학습 (SFT) | 선호 학습 (DPO / PPO) | RAG |
|---|---|---|---|---|---|
| 목적 | 일반 언어 능력 | **도메인 지식·용어·문체** | 대화 형식, 지시 따르기 | 더 나은 답 고르기 (정확성, 간결함, 실수 줄이기) | 최신·정확한 사실 전달 |
| 데이터 | 웹 전체 (수조 토큰) | **도메인 원문** (수백만~수억 토큰) | 질문-답변 쌍 (수천~수만 개) | 선호 쌍: 질문 + 좋은 답 + 나쁜 답 (수백~수만 개) | 검색 색인 (학습 없음) |
| loss | 모든 토큰 | **모든 토큰** | 답변 토큰만 | 좋은 답 확률 ↑, 나쁜 답 확률 ↓ (참조 모델 대비) | — |
| 모델 변경 | 처음부터 | 기존 가중치를 이어서 | 기존 가중치를 이어서 | SFT 모델을 이어서 | 없음 |
| 비용 | 수백만 달러 | **GPU 1장, 수십 분~수 시간** | GPU 1장, 수십 분 | DPO 는 SFT 와 비슷, PPO 는 몇 배 (학습 중 생성) | 임베딩 + 벡터 DB |

#### CPT, SFT, DPO 의 데이터는 이렇게 다르다 ####

```jsonc
// CPT: 원문을 그대로. 모든 토큰이 학습 대상
{"text": "# 파드\n\n파드(Pod)는 쿠버네티스에서 생성하고 관리할 수 있는 ..."}

// SFT: 대화 형식. assistant 답변 부분만 학습 대상
{"messages": [
  {"role": "user", "content": "파드가 뭐야?"},
  {"role": "assistant", "content": "파드는 쿠버네티스에서 ..."}]}

// 선호 학습: 같은 질문에 대한 답 두 개. 어느 쪽이 나은지를 학습
{"prompt":   [{"role": "user", "content": "파드가 뭐야?"}],
 "chosen":   [{"role": "assistant", "content": "파드는 쿠버네티스에서 배포할 수 있는 가장 작은 단위로 ..."}],
 "rejected": [{"role": "assistant", "content": "파드는 노드의 메모리 공간을 뜻하는 ..."}]}     // 그럴듯한 오답
```

CPT 는 **"무엇을 아는가"** 를, SFT 는 **"어떻게 답하는가"** 를, 선호 학습은 **"어느 답이 더 나은가"** 를 바꾼다.
실무에서는 보통 **CPT → SFT → DPO(또는 PPO)** 순서로 하고, 정확성이 중요한 부분은 **RAG** 로 보완한다.

### 3. 왜 base 모델인가 ? ###

| 모델 종류 | 예 | 특징 |
|---|---|---|
| base (사전학습만) | `Qwen/Qwen2.5-3B` | 문장을 이어 쓴다. 대화를 하지 못한다 |
| instruct (SFT + RLHF) | `Qwen/Qwen2.5-3B-Instruct` | 질문에 답한다 |

CPT 의 데이터는 "대화"가 아니라 "문서"다. instruct 모델에 문서 이어쓰기를 많이 학습시키면 대화 능력이 망가지기 쉽다. 그래서 **base 모델에 CPT 를 하고, 대화 능력은 나중에 다시 입힌다**


### 4. 토크나이저: 한국어는 비싸다 ###

실습 데이터를 Qwen2.5 토크나이저로 실제로 쪼갠 결과:

```
"파드는 쿠버네티스에서 생성하고 관리할 수 있는 배포 가능한 가장 작은 컴퓨팅 단위이다."
 48 글자 → 31 토큰

['파','드','는',' �','�','�','버','�','��','�','�','스','에서',' 생성','하고', ...]
                └──── " 쿠버네티스" (앞 공백 포함) 가 바이트 조각 8개로 쪼개짐 ────┘
```

- 단어 단위로 보면 `쿠버네티스` 7 토큰 vs `Kubernetes` 2 토큰, `파드` 2 토큰 vs `Pod` 1 토큰, `디플로이먼트` 6 토큰.
- 학습 데이터 전체 평균은 **1 토큰 ≈ 1.88 글자**다. 영어는 보통 4 글자 안팎이다.
- 모델이 잘 모르는 단어("쿠버네티스")는 UTF-8 바이트 조각으로 쪼개진다.
  CPT 를 하면 이런 조각들의 조합도 익숙해진다.
- 토큰 수는 곧 **학습 시간이자 비용** 이다. 데이터 규모는 글자 수가 아니라 토큰 수로 따진다.

### 5. full fine-tuning vs LoRA ###

```
full fine-tuning                    LoRA
┌──────────────┐                    ┌──────────────┐   ┌──┐
│  W (전부 학습) │                    │ W (고정)      │ + │BA│ ← 작은 행렬 두 개만 학습
│  30.9억 개    │                    │              │   └──┘   (rank r)
└──────────────┘                    └──────────────┘
```

| | full | LoRA (r=128, 모든 Linear) |
|---|---|---|
| 학습 파라미터 | 30.9억 (100%) | 2.39억 (7.8%) — Mac 에서 실측 |
| GPU 메모리 (3B) | ~40GB (fp32 가중치 + 8bit Adam) | ~16GB (bf16) |
| 지식 주입 | **강함** | 약함 |
| 일반 능력 망각 | 큼 | 작음 |

연구 결과 *"LoRA Learns Less and Forgets Less"* (Biderman 외, 2024) 에 따르면 LoRA 는 새 지식을 덜 배우는
대신 기존 능력도 덜 잊는다. 지식 주입이 목적이고 GPU 메모리가 충분하면 full 이 유리하다.
L40S 48GB 에는 3B full 학습이 들어가므로 이번 실습 기본값은 **full** 이다.

### 6. 파국적 망각과 replay ###

도메인 데이터만 계속 학습시키면 모델이 일반 한국어 능력을 잃는다.
대표적인 증상은 무엇을 물어도 쿠버네티스 문서체로 답하거나, 일반 상식이 흐려지는 것이다.

**대응: replay.** 일반 텍스트를 일정 비율 섞는다.

```
학습 데이터 = 쿠버네티스 문서 80% + 한국어 위키백과 20%   (build_cpt.py --replay-ratio 0.2)
```

### 7. 지식은 "여러 번, 여러 표현으로" 봐야 들어간다 ###

*Physics of Language Models Part 3.1* (Allen-Zhu & Li, 2023) 의 핵심 결론:

- 같은 사실이 **한 가지 문장으로만** 있으면 모델은 그 문장을 외울 뿐, 다른 질문에 그 지식을 꺼내 쓰지 못한다.
- 같은 사실을 **여러 표현(paraphrase)으로** 보여줘야 지식을 추출할 수 있게 된다.

그래서 이번 실습에서는:
1. **여러 epoch** (기본 4) 를 돌린다.
2. 선택 과제로 **영어 원문** 을 추가한다. 같은 내용을 다른 언어로 보는 효과가 있다.
3. 더 나아가려면 큰 LLM 으로 문서를 다른 문체로 다시 쓰는 **데이터 증강**을 한다.

### 8. Perplexity: 학습이 잘 됐는지 재는 법 ###

```
perplexity = exp(평균 loss)
```

직관적으로는 **"모델이 다음 토큰 후보 몇 개 사이에서 헷갈리는가"** 다.
값이 낮을수록 그 텍스트를 잘 예측한다는 뜻이다.

실습 환경에서 원본 Qwen2.5-3B 로 실제로 잰 값 (샘플 3개):

| 텍스트 | perplexity |
|---|---|
| 쿠버네티스 한글 문서 | 3.43 |
| 한국어 위키백과 | 5.04 |

쿠버네티스 문서가 더 낮은 이유는 YAML 이나 명령어처럼 예측하기 쉬운 부분이 많고 문체가 정형화되어 있기 때문이다.
**절대값보다 학습 전후의 변화가 중요하다.**

| 평가 세트 | 기대하는 변화 | 의미 |
|---|---|---|
| 학습한 k8s 문서 | 크게 ↓ | 지식 습득 (암기 포함) |
| 학습하지 않은 k8s 문서 | 약간 ↓ | 도메인 일반화 |
| 일반 위키 | 거의 그대로 | 망각 없음 |

### 9. SFT 다음 단계: 선호 학습 (DPO / PPO) ###

SFT 는 **정답을 따라 쓰는 것** 만 배운다. "이 답은 저 답보다 낫다", "이렇게 답하면 안 된다" 는 신호가 없다.
그래서 SFT 모델에는 그럴듯한 확각, 질문과 맞지 않는 답변, 그리고 문장의 반복과 끊김이 생긴다.
선호 학습은 **모델이 실제로 쓴 답 여러 개** 를 비교해서, 좋은 답의 확률은 올리고 나쁜 답의 확률은 내려서, 모델이 하는 실수를 직접 보여주고 고치는 방식이다.

```
           ┌── DPO: 선호 쌍으로 바로 학습 ──────────────────────────────────┐
SFT 모델 ──┤                                                              ├──▶ 선호에 맞춘 모델
           └── PPO (RLHF): 선호 쌍 → 보상 모델 학습 → 보상을 높이도록 강화학습 ─┘
```

| | DPO (Direct Preference Optimization) | PPO (RLHF) |
|---|---|---|
| 아이디어 | 좋은 답 / 나쁜 답의 확률 차이를 직접 벌린다 | 답에 점수를 매기는 **보상 모델**을 먼저 만들고, 그 점수를 높이도록 강화학습 |
| 필요한 모델 | 정책 + 참조 모델 | 정책 + 참조 + 가치 모델 + 보상 모델 |
| 학습 데이터 | 고정된 선호 쌍 (오프라인) | 학습 중 정책이 새 답을 계속 생성 (온라인) |
| 난이도·비용 | SFT 와 비슷. 단순하고 안정적 | 훨씬 복잡하고 느림. 하이퍼파라미터가 많음 |
| 대표 사례 | 최근 공개 모델 다수 | InstructGPT, 초기 ChatGPT |

두 방법 모두 **참조 모델(학습 시작 시점의 SFT 모델)에서 너무 멀어지지 않게** 묶어 둔다.
DPO 는 β, PPO 는 KL 벌점이 그 역할을 한다. 이 끈이 없으면 모델은 점수만 올리는 이상한 답(**보상 해킹**)으로 빠진다.
예를 들어 "짧을수록 좋다" 는 보상만 주면 결국 거의 아무 말도 하지 않는다.

#### 선호 데이터 만들기 ####

| 출처 | 예 | 특징 |
|---|---|---|
| 사람의 비교 | 답 두 개를 보고 더 나은 쪽 선택 | 가장 정확하지만 비싸다 |
| 사용자 피드백 | 👍/👎, 상담원이 수정한 답 | 실서비스에서 쌓인다 |
| **심판 LLM** | 큰 모델이 기준 답변을 보고 채점 | 싸고 빠르다. 길이·위치 편향에 주의 (이번 워크숍) |

> **핵심:** 선호 학습은 지식을 넣는 단계가 아니다. 이미 있는 지식으로 **더 나은 답을 고르는 습관** 을 들인다.
> 심판이 고른 "좋은 답" 도 완전히 정확하지는 않다. 덜 틀린 쪽을 배우는 것이라서 사실 정확성은 여전히 RAG 로 보완한다.
